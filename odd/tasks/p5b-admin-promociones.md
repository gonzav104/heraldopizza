# P5b — Administración de promociones

Objective: let the owner manage promotions from `/admin` (list, create closed or 12-empanadas combos, edit commercial fields, activate/deactivate, validity, weekdays, order) without code or SQL. Branch: `feat/p5b-admin-promociones` (from `main` at `50cf187`). Delivery: five work-unit commits; push, PR, and merge only with the user's authorization. Test runners: pgTAP (`npx supabase test db`), Vitest, Playwright E2E; browser checks in Chromium at 360/768/1280.

## Specs

- S1 Navigation (P5b-1): «Incorporá dos secciones en `/admin`: Carta, Promociones.» «Preservá la autenticación y autorización existentes.» «Extraé solamente las utilidades de guardado, errores y feedback realmente necesarias para compartir entre ambas secciones.» «El editor del catálogo debe seguir funcionando exactamente como antes.» Pending changes: «Preservar ediciones sin guardar al cambiar de sección.» «Bloquear navegación durante un guardado.» «Mantener la confirmación al abandonar el panel con cambios pendientes.» «Mantener el aviso `beforeunload`.» «Impedir que controles ocultos sean accesibles mediante teclado.» «Evitar recargas o solicitudes innecesarias de secciones que todavía no se visitaron.» «No introduzcas React Router ni dependencias nuevas sin una necesidad demostrada.»
- S2 Repository (P5b-2): `AdminPromotionsRepository`, `SupabaseAdminPromotions`, admin models, pure validators, error handling, optimistic concurrency with `actualizado_en`. «Listar todas las promociones. Crear promociones. Editar campos autorizados. Reordenarlas.» «Reutilizá el cliente autenticado existente de Supabase.» «El adaptador no debe enviar `codigo`, `id` ni los campos de composición durante una edición.» «Validá estrictamente las respuestas de Supabase.»
- S3 List and edit (P5b-3): title, description, price, visibility, validity dates, weekdays, order, informative status, non-editable composition. States: «Activa. Desactivada. Programada. Vencida. Fuera de día. Categoría de gustos oculta.» «Calculá los estados informativos utilizando la zona horaria `America/Argentina/Buenos_Aires`.» «No dependas de la zona horaria configurada en la computadora.» «La base de datos continúa siendo la autoridad de visibilidad pública.» «Implementá confirmación al desactivar, manejo de errores, conflictos de edición y recarga.»
- S4 Create (P5b-4): «A. Combo cerrado — Sin selección configurable de gustos.» «B. Docena de empanadas a elección — Exactamente 12 unidades de la categoría Empanadas.» «La interfaz no debe permitir configurar otras categorías o cantidades.» Code generated by PostgreSQL, never editable. «Las promociones nuevas deben crearse inicialmente con `visible = false`, enviado explícitamente desde el adaptador.» «No dependas del valor por defecto actual de la columna en PostgreSQL.» No product associations (RF-44 out of scope).
- S5 Order (P5b-5): «opción A: botones Subir y Bajar con operación atómica en PostgreSQL». «Creá una migración nueva posterior a P5a. No modifiques la migración de P5a ya fusionada.» Security: «Usar una función RPC con `SECURITY INVOKER`», «Respetar RLS y los permisos efectivos del administrador», «No otorgar privilegios de administración al público», «Restringir el permiso EXECUTE a los roles necesarios», «Usar identificadores y nombres de objetos calificados y un `search_path` seguro». Operation: «1. Identificar la promoción y su vecina según el orden vigente. 2. Validar permisos. 3. Comprobar tokens de concurrencia. 4. Bloquear las filas relevantes durante la operación. 5. Actualizar el orden de forma transaccional. 6. Fallar completamente cuando exista un conflicto. 7. Devolver un resultado que permita actualizar la interfaz sin asumir éxito.» «Contemplá posiciones repetidas, movimientos simultáneos y nuevas promociones.» «Definí un criterio estable de desempate.» Explain which invariants the database guarantees and which only the interface.
- S6 Tests: PostgreSQL (admin, non-admin, anon, valid/invalid create, immutable composition, dozen constraints, RPC privileges, atomic reorder, concurrency conflicts, no partial changes); frontend (navigation, unsaved changes, create closed, create dozen, edit texts and prices, activate/deactivate, dates and days, reorder, loading/empty/error/conflict, accessibility); E2E against local Supabase (new promo saved and read back; deactivated disappears from the reloaded public menu; price change reflected; dozen opens its configurator; concurrent changes not silently overwritten). Chromium at 360, 768, 1280.
- S7 Limits: no push, PR, or merge; no WhatsApp, search, images, or visual changes outside the admin; no remote Supabase; protect local data before any destructive operation; no refactors outside P5b.
